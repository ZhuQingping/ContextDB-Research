0. 设计结论与阅读边界
V2.5 将 Hindsight 放在
记忆与知识加工内核
的位置，复用事实抽取、关联检索、观察归纳、知识页和 PG 持久任务；产品层补足来源版本、可信共享、三业务资产、最后采用证据及恢复协议。Session、Skill 的事实权威不塞进记忆事实表。
狭义Gateway/API、Handler（前版称Business Runtime）、Worker必须独立且无状态；所有集群支持扩展，PG明确分离元数据/用户数据，LLM Adapter承担多租接入、计费、监控及管理。
 源码中协议、附件/输入处理、查询/反思及后台维护的混合，是本轮明确拆分的对象；容量数据只决定副本/硬件/自动化，不取消该边界。

1. 面向谁、三业务如何产生价值
产品面向需要跨会话、跨 Agent 保存和复用资料的平台团队。首个具名客户、任务族、宿主版本和规模尚 UNKNOWN。V2 用三条合成样例解释机制，样例不是客户事实，也不是已执行 Demo。
业务 / 整体目标
同一条正常链
两条必须成立的变化/失败链
首期 R1 提案与边界
K 企业知识与共享 / G-001
规范 K-A-r1 规定“导出需审批”，例外 K-B-r1 规定“仅全合成且未含生产字段可免审”；两份缺一不可。两 Agent 按不同 grants 查询、回原文、形成有来源回答
K-A-r2 改规则后旧页暂不可用；撤 Agent-B 的 grant 后搜索/直读/排队派生与下一使用均拒绝
版本化文本+Bank级共享+获授权联检+来源有效性+一个受控宿主；完整连接器、混合源细粒度ACL后置
M 个人长期记忆 / G-002
团队内成员M-U 在项目 P 常用中文，仅出差用英文；保存原事件/条件，抽事实与观察，再按当前问题回原文确认
迟到的旧事件不覆盖新偏好；宿主截断不丢“仅出差”条件；冲突不明时呈现两个有时间的来源
同主体/项目范围与当前/历史问法；画像/观察为可选派生；不承诺默认抽取无损
S 轨迹到可验证 Skill / G-003
Session S-1 中工具导出成功、S-2 正确拒绝、S-3 异步失败；从真实轨迹冻结 procedure v1，独立留出 Trial 后人工发布，宿主按前提加载执行
工具schema升级使旧 Skill 退役；假的success文本但外部文件未生成不得晋升；Trial明细丢失不得报已验证
原轨迹+人工/受控生成候选+独立Trial+显式Release+退役；不将 Hindsight page 当原生 Skill，不默认自动学习发布
G-004—G-008 贯穿三条链：预算内真实收益、可信共享、宿主采用、耐久运营、自主升级退出。每业务的正确率/失败分母独立；Memory 589题历史成绩不能验收 Knowledge 或 Skill。R1 每类至少一条正常和两条变化/失败路径，但实现顺序和门槛仍需用户接受。
产品负责接收版本、加工/检索/可用性、授权和服务收据；外部业务系统负责规则原始权威与有效期含义；模型负责有损提取/综合候选而不能批准事实或授权；宿主负责最终窗口、工具许可和任务执行；外部 oracle/审阅人负责 Skill 终态与发布批准。原始内容要求模型“忽略权限”时仍只是资料。
非目标：重新选择底座、通用图数据库自研、任意宿主的透明完全控制、自动执行不可信 Skill 脚本、单 Bank 跨 PG 多主、跨区域双活、无限离线授权缓存、外部模型费用 exactly-once。Graphiti、Cognee、OpenViking、ReMe、MemOS 和云合同是机制/反例参考，不因此进入必需依赖。

Bank：
REGISTERED → PROVISIONING → DATA_READY → CAPABILITY_READY → ACTIVE

索引：
REQUESTED → BUILDING → VALIDATING → VALID

FAILED/INVALID

删除：先Bank资格
DELETING
/拒新访问，保受理/计费/审计保留；业务内容清理、索引DROP、raw生命周期分别有收据，不让运行角色直接前缀清理原件。
开通/索引角色持限定Unit对象的DDL凭据；普通H/W只DML或受限过程EXECUTE。原生eager CREATE、threshold maintenance、import创建索引、delete的DROP、默认startup migration全列入口清单。推荐复用已存在的并发维护路径并改其身份/调度；不是再写一套不相关索引系统。
共享表已有其他Bank写入时，CREATE INDEX CONCURRENTLY在独立autocommit连接执行，不能放入业务受理事务。失败可能留下INVALID对象，重入先检查定义/有效性，不只IF NOT EXISTS；同一表并发构建要排队，扩展类型与并发能力逐profile核实。这些限定来自
PG18 CREATE INDEX

6.1 时间、查询类型与证据完整性
时间字段及选择算法
：SourceRevision表示一次不可变输入；Assertion另有
subject_ref, predicate, condition_scope_ref, valid_from, valid_to, event_at, asserted_by, authority_kind, supersedes[], conflicts[]

请求含

valid_at

known_at

known_at
不能直接用应用发起时间或事务内
now()
冒充提交可见时间。候选采用由既有PG WAL/恢复归档路径生成的不可变CommitReceipt（source/accepted_seq、事务提交水位、数据库提交时间、timeline/恢复epoch），异步关联受理记录；不新建raw日志或第二业务队列。
as_known

PG18逻辑解码回调
取得；具体产品接入仍是提案。捕获延迟、WAL解码/保留权限、时钟偏差和映射缺口进入DG-03/MP-08探针，未验前该历史能力不能标READY；now/valid_as_of仍按当前已提交可读集合执行。
选择顺序固定：①当前授权/删除门；②主体/项目/条件可判定性；③valid区间与可选known_at；④显式authority/优先级和supersedes；⑤同优先级互斥且无法裁定则返回
CONFLICT
及来源，不任选最大revision。revision是opaque业务版本，另外用单调accepted_seq处理CAS，不能做字符串大小比较。临时出差例外只在明确条件成立时覆盖常态；条件未知返回条件分支或澄清需求。
未来激活采用“持久activation operation预热+读取时兜底”，延迟调度不得改变正确选择。缓存key包含query语义、Source选择/Build、授权域和policy版本；

10.3 扩缩容决策闭环：指标→判断瓶颈→准入→分配→观察
扩展能力来自上面的可分配工作/外部状态与受控映射；自动控制器只是执行方式。首期可由运维按同一协议审批并执行扩容计划，后续再自动化，不能删除必要的池注册、配额、租约和epoch保护。
观察
：G采集认证/授权/限流/路由各阶段延迟、连接数和拒绝原因；Handler上报在线等待/CPU/在途请求；W上报可执行任务的积压年龄与预计剩余工作量；L和PG/OBS上报自身等待/配额/资源饱和。撤权阻塞、等未来时间、失败待人工处理的任务不能一概算可执行积压。
判断
：区分本层算力不足与下游受限。若模型429/预算耗尽、PG锁/IO饱和、OBS配额受限，先限流/背压或处理相应瓶颈；单纯加Handler/Worker通常只增加等待、连接和重试费用。按任务类别分池测服务时间，不把轻查询与长Reflect平均成一个数。
准入
：扩容计划检查实例预算、PG连接余量、Tenant/Subtenant/模型/入口全局额度、可用节点、profile/DDL/payload兼容性和允许的最大并发。可用槽位为0时不向新实例发工作。
加入
：新实例取得服务身份与独立incarnation，加载可信目录/兼容profile，通过就绪检查，再注册服务发现/assigned Unit。G从负载均衡获得新连接，Handler从G获同池请求，W从PG claim工作，L通过持久幂等/额度发模型请求。扩容不是复制某旧Pod内存。
确认与回退
：比较同负载下本层排队、成功吞吐、尾延迟、拒绝、PG/provider压力与成本；无改善或恶化就停止增副本、收回未用分配并定位瓶颈。观察窗口/冷却期/每次最大变更/上下阈值应预先配置且有滞后，数值目前UNKNOWN，避免上下抖动。
缩回
：先停止新连接/请求/任务领取，排空在途；未完成工作保留耐久checkpoint并封旧attempt。确认旧实例不能消费后才回收其额度。进程突然退出按持久租约接管；未知模型外发仍挂原ProviderAttempt费用敞口，不因缩容清零。

10.6 PG读扩展、写扩展、连接与热点的具体边界
PG18热备机制
支持standby上的只读查询；它不会让同一PG成为自动多主写库。读副本只有追平要求的发布/源水位且安全资格仍由当前authority判定，才可承接对应查询；落后时回主库、等待或明确不可满足，不把缺行当事实不存在。身份/撤权/预算/claim/合法发布等要求当前权威的写事务不发只读副本。
纵向扩容CPU/内存/IO/存储可缓解单写组资源压力，但不能证明某类锁争用会消失。水平写扩展采用已有storage placement按Unit把

16.1 逻辑键、逐次预算与兼容/失败覆盖
ModelCall逻辑键绑定tenant、initiating/effective principal、operation/phase（或query）、语义输入hash、用途和profile；ProviderAttempt另有不可复用attempt_id/owner_incarnation/send_nonce和
实际wire hash
。模型兼容修复、重试、failover、区域/credential切换每次建立新attempt，付款归原payment route。仅wire字节相同不允许跨授权域复用缓存；模型/输入前缀/空间/参数不相容不能共用embedding。
同一Tenant-home事务检查父Tenant与子主体/任务的
已结算 + 在途预留 + UNKNOWN敞口 + 本次最大可核成本 ≤ cap
，一次性登记reservation。没有可核成本上限的供应商形态不声明硬费用帽；严格档禁用无取消/到期/用量合同的远端batch。预估上界、实际用量和客户计费分别存，价格版本、货币、provider/credential/payment route不可随重试偷换。未知费用不记零，也不靠TTL释放；已知未发送且取消有证据才退还该预留。并发slot与金额/token是不同量纲。
覆盖矩阵包括generate/工具兼容修复、embedding/rerank主/备provider、CoalescingEmbedder、local执行、cache命中、batch、init probe和后端自带full_recall。默认关闭SDK隐藏重试；不能关闭时必须在每实际send前后hook产生attempt/usage，未能逐次捕获则该路径不开放。连接、首token、末token、OBS capture和result-ready分段计时；安全审计、原始nullable usage与完整失败分母保留。
