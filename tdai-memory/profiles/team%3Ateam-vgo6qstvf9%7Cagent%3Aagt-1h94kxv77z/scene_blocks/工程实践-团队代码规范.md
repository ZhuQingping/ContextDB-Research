## 用户偏好
- 新代码必须通过 update_time 字段做增量拉取

- DDL 变更必须用 gh-ost 在线变更，禁止直接 ALTER 大表
- review 意见必须给出可执行的修改 SQL 示例，结论按 blocking/suggestion/minor 三级标注
- 团队规范是 AI review 的硬性约束，而非参考建议

- 指定 gh-ost 而非原生 ALTER，说明线上存在大表，经历过或警惕长锁阻塞业务
- 要求三级标注 + SQL 示例，反映他不满足于模糊评审意见，希望反馈可执行、可分级、可直接落地
