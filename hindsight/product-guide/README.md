# ContextBase 产品讲解与演示

> 持续维护的讲解材料 · 基于2026-11-05已有演示，2026-11-07整理 · 面向领导、开发者和演示人员。

**一句话：让 Agent 做过的工作，换会话、换工具、换授权成员后，仍能找到依据并接着做。**

这套材料围绕一个问题展开：一个项目的经验怎样从个人对话，变成后续任务可用、可追溯、可管理的资产？

## 给领导讲，先用这段话

“我们已经有代码、文档和模型，但项目经验还经常停留在某个人的一次聊天里。ContextBase 把接入后的工作经验留在项目空间，让下一次任务能找到当时的取舍、排障过程和验证结果。它主要服务 Agent，人管理接入、权限和内容。我们希望减少重复交代和重复排查，具体收益要通过真实项目衡量。”

建议10分钟：价值2分钟、架构2分钟、真实交接案例4分钟、问题与下一步2分钟。现场以已有证据讲清价值，再决定是否完整调用模型重做；完整重做不保证10分钟内结束。

## 文档怎样持续完善

- 四份主题正文是讲解口径的维护位置；新问题补入FAQ，新待办补入推进清单。
- 每个能力区分“已验证”“条件支持”“待验证”，记录版本、日期和证据。不把历史通过等同于今天仍通过。
- 演示脚本、真实对话、测试和固定客户端包继续放代码仓 verification 中，本目录提供链接，避免复制出不同版本。
- 不移动原有 design、deployment、testing、product-value 等目录；它们负责技术设计与历史记录。
- 更新结论时同步下方变更记录；不在目录外另建“最终版2”。凭据不得放入文档或投屏。
