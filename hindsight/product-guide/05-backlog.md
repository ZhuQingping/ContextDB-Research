## 优先优化：Hook 静默失效与客户端接入可观测性

记录日期：2026-11-08。建议优先级 **P1**；状态：问题已复现、优化待设计与实施。用户明确要求：客户端接入不生效时必须能发现，不能依赖人工抓日志才知道。

**实际问题：** outer_space 的 UserPromptSubmit 修改执行上限后，配置仍显示 enabled，但信任状态为 modified。SessionStart、MCP 与 Stop 可继续工作，聊天也能正常回答，用户因此难以察觉自动回忆没有执行。无请求也意味着服务端没有对应失败调用，单看 API 健康或服务端错误日志无法发现。上轮 [真实证据](07-agent-knowledge-interaction-20261108.md#hook-trust-incident)确认该缺口；重新信任后的 [复验结果](07-agent-knowledge-interaction-20261108.md#latest-verification)用于核对实际恢复，不能据此认为产品可观测性问题已经修好。

| 优化项 | 期望行为与验收标准 |
| --- | --- |
| 安装、升级、修改配置后自检 | 查询宿主实际加载的三个 Hook，分别报告 enabled、trustStatus、当前配置是否与受信任配置一致。修改 timeout 等字段后明确提示重新确认信任，不只提示重启 |
| 用户能看到当前接入状态 | 分别展示自动读取、MCP 工具、自动保存的状态；不能用“已连接”“MCP 正常”或安装成功概括全部能力。待验证就显示待验证，不误报正常 |
| 未执行也能被发现 | 检查宿主状态的入口应独立于目标 Hook，例如独立诊断能力或宿主集成；不能要求被跳过的 Hook 自己输出失败日志。只有服务端无流量不足以判定，需要结合应触发事件与宿主信任状态 |
| 会话级执行证据 | 按 session_id、轮次、事件记录触发/跳过/执行结果、原因、耗时、降级来源、operation_id。区分尚未触发、被禁用、未信任/已修改、成功、失败及未观测到；不能混为“没有记忆” |
| 发现异常后给出可操作提示 | 例如“自动读取记忆未运行：提问 Hook 配置已变更，请核对并重新信任”；显示受影响项目和功能。避免每轮重复打扰，不暴露密钥或完整对话 |
| 自检遵守权限边界 | 不自动修改 trusted_hash，不绕过用户确认。能检查工具未加载、配置与实际进程不一致；不能仅读取磁盘配置后声称当前运行正常 |
| 读取和保存分别验收 | 首轮自动 Reflect/降级、后续目录更新、MCP 工具发现与实际调用、每轮保存及后台完成分别有证据。考虑缓存/autoInject 配置：不是每轮都应 Reflect，不能把预期不调用误报成故障 |

**关闭标准：** 复现未信任、modified、disabled、调用超时、工具未加载等场景时，用户可通过明确状态和操作指引发现问题；正常新会话能展示对应执行证据；服务端健康且 MCP 可用时，仍能准确指出哪个自动环节失效。上游客户端无法提供的信号需标为未知，不能伪造确定状态。

以上是后续产品优化要求，本次记录没有实现自动巡检、监控或告警，也没有创建定时任务。

## 待评估：召回统计覆盖默认Reflect路径

记录：2026-11-08。现有特性`9a5ba2c6`按原设计统计外部Recall与知识搜索，排除Reflect内部检索及正文读取。默认Hook走Reflect时，memory虽被检索，当前统计也可能没有新增；不能用计数为0或时间旧判断没有使用记忆。

后续评估保留直接检索口径，增加外部Reflect命中和知识全文读取的渠道指标，根请求内按对象去重，排除后台维护；区分检索命中与回答引用。不得直接累加内部每次Recall或静默改变历史计数语义。状态：待设计、未实施。详细证据与方案边界见[召回统计设计补充](../design/contextdb-recall-usage-design.md#2026-11-08-复核默认reflect场景的统计覆盖缺口)。
