# ContextDB 差异化：先明确增量价值，再谈领先

本轮修订：此前“做好Coding Agent接入”只说明入场路径，没有证明竞争力。**远程Hindsight、跨会话记忆、官方客户端插件、API key均已存在，不能作为华为云独有能力。当前没有同条件竞品试用或生产客户数据，不能宣称准确率、价格或体验领先。**

## 1 原生已经做到什么

| 能力 | 证据 | 是否算我们的差异化 |
|---|---|---|
| 远程API与Bearer key | 上游SDK、Hindsight Cloud官方文档 | 否 |
| Claude/Codex远程记忆与仓库Bank | 当前统一`coding-agents`插件，支持URL/token配置 | 否 |
| Hermes/OpenClaw接入 | 上游插件及本轮客户端验证报告 | 否；兼容性仍需按版本验收 |
| Retain/Recall/Reflect、向量/全文/关系检索 | 当前源码和本地服务 | 否，是底座 |
| 开源PG存储与任务机制 | 源码及本地PG验证 | 否；使用PG本身不代表客户获得更好体验 |

实测Hermes为AIAgent核心，Claude Code/OpenClaw使用既有GLM后端，均连接本机Hindsight；不是四客户端所有运行面或华为云公网认证验收。

本轮没有把“CLI能启动”“MCP工具能列出”“插件unit通过”当成完整客户端通过；真实会话结果见 [客户端报告](../deployments/hindsight-local/round2/reports/clients.md)。新版Coding插件默认注入可涉及Reflect，因此“默认不做额外生成”需要我们配置并实测，不是原生已经保证。

来源：[统一Coding Agents源码](../../hindsight/hindsight-integrations/coding-agents/README.md)、[官方API接入与key管理](https://docs.hindsight.vectorize.io/api-integration/)。

## 2 最优先的增量：团队知识可以放心复用

**建议第一个可交付卖点：个人排障记忆可以晋升为带来源、适用版本和审核记录的团队知识，且权限、撤回和恢复行为可验证。**

具体用户路径：个人Agent记录故障→选取来源生成/编辑草稿→团队负责人审核→团队KB发布→新成员在后续任务召回→资料过时撤回。客户看到的是“新成员拿到经过审核且适用当前版本的经验”，不是多了几个技术接口。

| 增量 | 相对直接托管Hindsight增加什么 | 实现取舍 |
|---|---|---|
| 个人/团队Bank授权 | 同一团队成员不能任意读他人私有记忆 | 先做按库授权，不做段落级ACL |
| 来源与审核 | 区分个人经历、推断和正式规范 | 固定模板+人工审核，不做自动审批算法 |
| 版本与适用条件 | 记录PG/MySQL版本、现象、原因、步骤、回退和来源 | 先人工填关键字段；金标验证后再增加自动抽取 |
| 撤回与恢复 | 过期知识不继续被召回或因恢复重新公开 | 首期按KB暂停查询完成变更，降低并发版本系统成本 |
| 可诊断 | 用户知道写入待处理、失败、已可检索及来源 | 复用operation，不另造完整任务引擎 |

这是相对原生部署的**产品增量**，不是市场独有：阿里云等也已有团队知识/晋升描述，不能只凭功能名称称竞争壁垒。华为云的机会在已有数据库客户、DBA经验与交付体系；这些资源能否转成更快接入和更少错误，需要试点确认。

已有本地证据：27项key/Bank ACL检查、14项发布状态PG合同检查；原生删除来源后衍生知识仍可能保留的实验说明为什么需要治理。它们证明选题和局部机制，不证明整个知识产品已完成。[鉴权结果](../deployments/hindsight-local/round2/evidence/auth-probe.json)、[发布合同结果](../deployments/hindsight-local/round2/evidence/publication-probe.json)、[删除实验](../deployments/hindsight-local/evidence/source-delete-check.json)

## 3 第二增量：客户能控制成本，也能解释失败

不以“更省Token”作未经测量的承诺，先提供可操作的控制：

- 普通记忆查询使用有预算的Recall，客户显式选择Reflect或插件的相应注入模式。
- 用确定性document/session ID与幂等键减少客户端重复传输；不同正文复用同一key必须拒绝，避免静默忽略更新。
- 规范KB采用原文块，不默认每次做事实抽取和自由整合。
- 显示前台与后台调用、失败重试、任务积压；输入量、任务数、并发和保留期有明确限制。
- 用完整任务成本比较：LLM抽取/整合/Reflect + Embedding/Rerank + PG/存储/运维，不能只看Recall输出Token。

本轮已发现并验证原生Retain的operation重放不会校验正文一致；控制PG摘要账本能补这个合同，11项检查通过。[证据](../deployments/hindsight-local/round2/evidence/idempotency-probe.json)

精确人民币硬预算需要覆盖全部模型出站与重试，本期不能把入口限流包装为已实现费用硬上限。是否比默认配置更便宜，要在任务成功率不下降的条件下实测，当前不提供节省百分比。

## 4 用什么证明价值，投入多少

建议首批选择2–3个现有数据库团队，整理30–50条获准脱敏任务；以下是验收设计，不是当前成绩。

| 验证目标 | 对照与指标 | 否定该方向的证据 |
|---|---|---|
| 新成员更快复用经验 | 原生Hindsight vs 新知识流程；完成时间、正确适用版本、来源可查率 | 审核维护成本超过节省的查找时间 |
| 权限与撤回可靠 | 私有/团队/离职/撤回/恢复矩阵，所有公开读取路径 | 任一未经授权正文外泄即阻断上线 |
| 接入更简单 | 非作者按文档接入；首次真实跨会话成功耗时、失败定位时间 | 只能由开发者手工调环境才能成功 |
| 同质量更可控的费用 | 固定模型、同样任务/预算，记录全部调用和完成率 | 少Token但任务失败率上升，不算成功 |
| 数据库场景更准确 | 不用记忆/普通RAG/原生Hindsight/拟上线配置；留出领域金标 | 无稳定增益则不自研检索算法 |

性价比顺序：先完成共享的身份/任务/来源基础，再做一个审核发布闭环，随后做成本明细；先不做几十种Agent适配、自训模型、复杂图引擎和自动化数据库操作。

投入已并入 [开发任务板](cloud-service-architecture.md#10-五人可执行任务板)，不要把这里的价值方向另加一轮工期：D03身份权限18人日、D06连接与首客户端14人日、D08知识闭环20人日、D07模型/用量14人日、D11领域验证10人日。这是估算，依赖现有云配套，尚无实际交付工时证明。

## 5 上线承诺如何写

首期可以在验收后承诺“支持指定客户端版本、个人记忆与团队KB按库隔离、审核发布与来源追溯、可查询的任务与用量”。

暂不承诺“比竞品准确率更高”“必然更省Token”“所有客户端都自动记忆”“彻底删除所有历史影响”“任意规模透明扩展”。商业GA仍需目标RDS/MaaS/网关的生产验收，不能用本机原型替代。

长期能形成积累的资产是：数据库场景的失败样例、获准使用的金标、来源/版本反馈和稳定服务能力。**这些资产是否形成竞争壁垒要靠持续试点结果证明；目前应把它们称为投入方向。**
