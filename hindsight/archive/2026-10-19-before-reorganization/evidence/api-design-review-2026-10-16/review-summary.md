# API 设计审查共识

日期：2026-10-16。仅设计与文档审查，无源码/运行服务/数据库修改。

## 结论

REST/Web、UI、Agent 三位专家独立审查并交叉复核，主控整合；**文档目标方案 ACCEPT，当前实现仍为 REVISE**。这不是新接口、生产安全或性能验收通过。

保留当前 14 个管理操作。首期围绕一个授权对象、只改名不改权限、吊销后的正常列表、可恢复的空间进度和明确的超时重试完善，复用现有 Tenant/HTTP/Validator/MCP 插件及原生内容 API。

首发阻断：原生 REST 任务详情 include_payload 的普通读权限可达包含 Webhook secret/http_config 的任务原始载荷。Agent 专家发现，主控和 REST/Web 专家独立静态确认；未请求真实敏感数据，未隔离动态复现。原生 MCP 当前不暴露该参数。必须用合成凭据在隔离环境复现并关闭，再作运行安全验收。

## 专家意见与取舍

| 专家 | 独立审查主要结论 | 最终文档复核 |
| --- | --- | --- |
| REST/Web | 14 路由保留；authorization 两种互斥模式；PATCH 显式替换；统一代理/API合同；无明文重放 | 方案可接受；要求明确重复布尔参数拒绝，已落实 |
| UI | 仅改名、脱敏/吊销分页、失效授权回显；管理目录看见非 active 状态；保存原始意图 | 方案可接受；要求刷新仅 GET、未知结果明确点击才重放，已落实 |
| Agent | 逐目标空间授权贯穿执行；MCP 发现不等于权限；运维载荷旁路首发关闭 | ACCEPT；建议明确本次已确认入口为 REST，已落实 |

补充的三项修订：

1. include_payload 重复参数拒绝 400；单值真值对业务身份拒绝 403，合法假值保留查询，非法值拒绝，正常处理编码及大小写。
2. 页面刷新不自动重放 POST/DELETE。无 operation_id 时标记未知，明确提示可能重启失败任务，管理员主动继续才按保存意图重放。
3. 敏感载荷问题不扩大为未证实的 MCP、日志或配置泄露；其他诊断读取列待核查。

## 首期不做

不加实例 HTTP 管理、成员角色/成员级 ACL、管理 MCP、全空间授权例外、Key 明文恢复、通用创建幂等平台、历史吊销列表、操作取消/强制删除或新的节点 Agent 协议。默认读写保留，范围仍显式选择。性能改动需测量，不跨请求缓存权限。
