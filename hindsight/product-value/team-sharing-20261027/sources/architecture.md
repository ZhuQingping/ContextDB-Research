# ContextDB 团队共享的架构与权限

这份资料由 Codex 于2026年10月27日从项目已有设计和代码整理，未经过人工产品审批。来源为 integration/rsixdb-contextdb/docs/contextdb-management/DESIGN.md、hindsight-extensions/contextdb-service/README.md 和权限系统测试，源码核对版本 cdd067170。文档ID：team_demo_architecture_20261027。

ContextDB 基于 Hindsight 增加独享实例的工作空间、用户和 API Key 管理。一个实例使用一个PG数据库；一个工作空间对应一个Bank，空间有独立schema。工作空间是团队内容与访问权限的边界，空间内的记忆和知识可由具备权限的成员Agent复用。

用户记录Key的归属，授权配置在Key上。不同用户各自持有Key，同一Key可被授予多个工作空间的不同权限。read允许Recall、Reflect和读取已有文档及知识；read_write允许Retain及允许的内容变更。工作空间生命周期、用户和Key管理由管理员负责。首版UI是管理员入口，普通业务成员通过各自Agent的REST或MCP使用共享知识，不能把只读业务Key当作UI登录账号。

共享空间里的内容按空间授权共享，不提供阿里云产品那种同一空间内默认每人私有记忆隔离。个人秘密或未评审实验记录不应直接进入全员共享空间；需要私有或受限内容时，使用独立授权空间。目录用于组织知识，不应当作权限边界。

Retain存入原始资料并提取记忆事实；知识页围绕source_query从证据生成主题文档。知识页有独立搜索与读取接口，单独调用Recall不会自动遍历所有知识页。Agent使用时应先搜索相关知识页并读取全文，再视需要检索原始记忆和文档。自动写入和调用时机由客户端Hook、集成或工作流配置决定；仅连接MCP不保证每轮自动记录。

共享知识仍需标明来源、适用版本、状态与维护责任。当前原生知识页生成与刷新不等于专家审批发布。审批、默认个人私有记忆、收益统计都不能仅凭有知识页就宣称已经提供。
